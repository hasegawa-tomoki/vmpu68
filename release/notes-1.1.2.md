VMPU68 1.1.2 — 10 MHz 動作時の HD 起動不能の修正と JIT の速度改善(Raspberry Pi 4 カーネル 1.1.2 / FPGA 1.0.0)

## 修正・改善
- 基板 V2.0.1 で X68000 のバスクロックが 10 MHz のとき(XVI のクロックスイッチが 10 MHz 側、ACE/EXPERT/PRO/SUPER など)、SCSI の DMA 転送がシャドウRAM に反映されず、IPL が「ディスクから起動できません」で止まる、Human68k が「無効なメディア」を出す、という問題を直しました。
  原因は SMI 転送のストローブのタイミングが 16 MHz(FPGA 内部 64 MHz)前提で、10 MHz(内部 40 MHz)では連続転送を取りこぼしていたことです。バスクロックを測って 10 MHz 級と 16 MHz 級でタイミングを切り替えます。SMI を有効にするときの自己検査にも連続転送(書込み 256 回、読み 256 回)を加え、通らなければ GPIO 転送に戻ります。
- JIT で、起動時に一度コードが置かれた領域(のちにプログラムのスタックや作業領域になる)への書込みのたびに不要な検査が走り、浮動小数点や三角関数の処理が遅くなっていた問題を直しました(Winner2 の triangle が 12.5 倍 → 17.2 倍、total 13.5 倍 → 14.4 倍)。「翻訳済みコードあり」の印を 256 バイト単位から 32 バイト単位にし、生きたコードが無くなった印は書込み時に下ろします。無効化の判定には書込み幅(1/2 バイト、DMA のバイトイネーブル)を使います。
- Web API に `/api/con?cmd=<コンソールコマンド>` を追加しました。J3 のシリアルを繋がなくても、コンソールコマンド(st、smi、ewait、jit など)を HTTP で実行して結果を文字列で受け取れます(reboot などの後続動作は行いません)。
- vmpu68.cfg に `smi_t=div,ws,wst,wh,rs,rst,rh,pace` を追加しました(SMI のタイミングを手動で固定したいときだけ。通常は不要)。

V1.0 の基板には SMI 関連は影響しません(SMI は V2.0.1 以降のみ)。JIT の改善は V1.0 にも有効です。FPGA のビットストリームは 1.0.0 のまま変更ありません。

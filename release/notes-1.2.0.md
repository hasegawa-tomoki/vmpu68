VMPU68 1.2.0 — バス出力をバスクロック同期にして安定性を向上 (Raspberry Pi 4 カーネル 1.2.0 / FPGA 1.2.0)

## 修正・改善

- 電源を入れた直後の数分間、16 MHzでVMPU68からメインRAMへの書込みが1/100ほど欠けていた問題を修正しました。
  - 電源投入から時間がたつと1/100万以下になるため、起動直後だけ目立っていました
  - FPGA はバスクロックの 61/16 倍の内部クロックでバスクロックをサンプリングして動作しており、そのタイミングでAS や DS、アドレス、データ出力のタイミングを決めていたため、そのタイミングがサイクルごとに約 16 ns の幅で揺れ、動作に影響を及ぼしていました
  - 対策としてすべてのバス出力を、バスクロックに同期して出力する様にしました
- X68000 XVI のクロックスイッチ(10/16 MHz)を切り替えてリセットスイッチを押すと起動まで長い時間がかかる問題を修正しました
  - リセットの最中にクロックが切り替わるとX68000本体がしばらくメインRAMへの書込みを受け付けない状態になり、起動時のRAM書込テストが長引き、ウォッチドッグがハングアップと判断して Raspberry Pi が再起動していました。 
  - 対策としてカーネルがバスクロックの変化を検出したら、クロックが安定した状態で X68000 にもう一度リセットをかけてから起動するようにしました
- メインRAMへの書込にまれに失敗する問題を修正しました
  - 書込みストローブの解除が本物のMC68000より半クロック早く、メインRAMの4ビット幅DRAMのうち1個だけ書込みが失敗することがありました
  - 書込みストローブの解除を MC68000 と同じタイミングにし、書込みデータもストローブ解除後 少なくとも半バスクロック保持する様にしました
- DMAC のバースト転送の直後に CPU がその領域を読むと、ごくまれに転送前の内容が見えることがある問題を修正しました。
  - 転送中にスヌープ(DMAC の書込みをシャドウ RAM に反映する仕組み)の記録があふれ、実RAMからシャドウRAMへの反映の前に CPU がシャドウRAMを読み込みすることがありました。
- Pi コンソール(J3 のシリアル、または `/api/con?cmd=`)にいくつかのコマンドを追加しました。
- HTTP API `/api/status` のレスポンスにいくつかの項目を追加しました
